Section 01Current project assessment

What this app is. new_power is a Flutter 3.38.7 / Dart 3.10.7 field-sales operations app for construction sales representatives. 290 hand-written Dart files (509 including generated code) in a feature-first Bloc/Cubit + GetIt + Retrofit/Dio architecture. Six feature modules: auth, projects (registration, activities, outcomes, stakeholders, map picking, file / voice / photo attachments), catalog, notifications (FCM + in-app inbox), user, onboarding. Bilingual AR/EN with RTL, custom light and dark theming, IBM Plex Sans Arabic.

Health of the codebase: good

flutter analyze returns 6 issues, all informational — 2 unused private declarations, 3 naming lints, 1 unused widget class. All 15 tests pass. There are no hardcoded UI strings, no http:// endpoints, no localhost leftovers, and no committed secrets beyond the Google Maps keys. The networking layer — single-flight token refresh, disciplined 401-vs-403 handling, explicit FormData-stream rejection — is unusually well considered.

Section 02Everything that must be done

Must do before release

Build

B1Android release build fails on desugaring artifact resolution

Verified by running flutter build apk --release:

Execution failed for task ':flutter_local_notifications:generateReleaseLintModel'.
> Could not find desugar_jdk_libs-1.2.2.jar
  (com.android.tools:desugar_jdk_libs:1.2.2)

flutter_local_notifications-18.0.1/android/build.gradle:45 pins com.android.tools:desugar_jdk_libs:1.2.2 for its own subproject. Only 2.1.4 exists in the local Gradle cache, and dl.google.com is unreachable from this machine. The existing subprojects { resolutionStrategy } block in android/build.gradle.kts forces AGP only, and only on the classpath configuration — which is why it does not cover this.

B2iOS has no CocoaPods integration

No ios/Podfile exists, and ios/Flutter/Release.xcconfig contains only #include "Generated.xcconfig" — the Pods-Runner.release.xcconfig include that pod install adds is absent. iOS has never been built.

B3iOS deployment target is too low for its own dependencies

project.pbxproj:349 sets IPHONEOS_DEPLOYMENT_TARGET = 13.0 and AppFrameworkInfo.plist sets MinimumOSVersion 13.0. But google_maps_flutter_ios 2.18.4 declares s.platform = :ios, '14.0'. pod install will refuse to resolve.

B4Files the build requires are untracked in git

git status shows these as ??: lib/firebase_options.dart, lib/features/notifications/data/repo/push_service.dart, lib/features/catalog/ui/widgets/catalog_image.dart, lib/features/projects/ui/widgets/stakeholder_slot_field.dart, android/app/google-services.json, ios/Runner/GoogleService-Info.plist, assets/images/newpower-logo.svg.

A clean checkout does not compile. Any CI, any second machine, and any recovery from this working copy is broken.

Identity & signing

B5Android application ID is still the placeholder

com.example.new_power in both namespace and applicationId (android/app/build.gradle.kts:11,35). Confirmed present in the merged release manifest as com.example.new_power.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION. Google Play rejects com.example.*, and this value is permanent once published.

B6iOS bundle identifier is still the placeholder

com.example.newPower appears in the pbxproj, in GoogleService-Info.plist (BUNDLE_ID), and in firebase_options.dart:69.

B7Android release signs with the debug keystore

android/app/build.gradle.kts:44-47. There is no key.properties and no .jks anywhere in the tree. Play rejects debug-signed uploads.

B8iOS has no signing configuration and no entitlements file

CODE_SIGN_IDENTITY[sdk=iphoneos*] = "iPhone Developer", no DEVELOPMENT_TEAM, and find ios -name "*.entitlements" returns nothing.

Without an entitlements file carrying aps-environment, iOS push notifications will not function at all — the entire PushService is inert on iOS.

Functional & release-mode

B9Release builds block login on emulators, and can permanently lock out real users

device_integrity_service.dart:35 — emulator detection is gated if (!kDebugMode). AuthRepository._integrityGuard() runs before register, login and verifyOtp, returning DEVICE_INTEGRITY_FAILED. Two consequences:

  • Google Play's pre-launch report and Firebase Test Lab run on virtual devices — they will report the app as unusable.
  • _check() defaults to true (compromised) when the underlying call throws, and safe_device's Android root check has well-known false positives on OEM ROMs. A legitimate user hitting either case is locked out of the app forever with no recovery path.
B10Server error messages are corrupted before display

ApiErrorHandler._sanitizeMessage (api_error_handler.dart:161-201) replaces \b(SELECT|FROM|WHERE|INSERT|DELETE|UPDATE|DROP|TABLE|CREATE|ALTER|EXEC|EXECUTE)\b with [sql], and any /… sequence with [path].

Every feature Bloc displays error.message verbatim — listErrorMessage: error.message in projects_bloc, activities_bloc and outcomes_bloc; error.message ?? 'Login failed' in login_cubit.dart:74. So "You cannot update a confirmed outcome" renders as "You cannot [sql] a confirmed outcome", and "Owner/Manager required" becomes "Owner[path]". This affects essentially every business error in the app.

B11Five localization keys used in code exist only in Arabic

error_rate_limited_login, _register, _otp, _forgot_password and _reset_password are defined in ar_sy.dart:854-864 and consumed by five auth screens, but are missing from en_us.dart.

AppLocalizations.translate returns the raw key on a miss (_localizedStrings[key] ?? key) — despite the doc comment claiming an English fallback. An English-speaking reviewer who trips a rate limit sees the literal text error_rate_limited_login.

B12Android auto-backup will brick restored installs

The manifest sets no android:allowBackup, so it defaults to true. SecureStorageHelper uses AndroidOptions(encryptedSharedPreferences: true), whose keys live in the hardware keystore and do not migrate.

On a device-to-device restore the prefs blob is present but undecryptable → readSafe throws SecureStorageException → AppStartupRouter.resolve() catches it and routes to startupError permanently, and the Dio onRequest interceptor throws on every subsequent request. Confirmed in the merged release manifest: no allowBackup attribute, androidx.security_security-crypto present.

Store policy

B13No in-app account deletion

The app supports account creation (/auth/register; RegisterScreen is routable). Apple Guideline 5.1.1(v) requires in-app account deletion for any app offering account creation. Google Play's data-deletion policy requires both in-app deletion and a publicly reachable web URL.

api_constants.dart has no delete or deactivate endpoint — this requires backend work, not just UI.

B14Photo and video permissions are merged in but not needed

Verified from build/app/intermediates/merged_manifests/release/processReleaseManifest/AndroidManifest.xml:

android.permission.READ_MEDIA_IMAGES
android.permission.READ_MEDIA_VIDEO
android.permission.READ_MEDIA_AUDIO

All three come from open_filex, which only ever hands app-internal downloaded files to the OS viewer. Play requires a Photo and Video Permissions declaration for these and rejects apps whose declared use is not core functionality.

B15No privacy policy exists

Required as a Play listing URL, for the Play Data Safety form, and for App Store Connect App Privacy. The app collects location, camera images, audio, device identifiers and account data.

B16Reviewers cannot create an account

Registration requires a managerCode (SM-XXXXXXXX, validated in register_request.dart:114). Both stores need a working demo account plus written walkthrough instructions, or the submission is rejected as "unable to review".

B17The app icon is a non-square wordmark

assets/images/icon.png is 896×1200. flutter_launcher_icons squashed it into 192×192, 432×432 and the iOS 1024×1024. Rendered and inspected: the result is a horizontally-compressed "NEW POWER" wordmark floating in white space, illegible below roughly 120 px.

Worse, the Android adaptive icon inset is only 16%, so the circular launcher mask will clip the wordmark to read "EW POWE".

Should do before release

S1Restrict the Google Maps API keys

Two distinct unrestricted-looking keys are hardcoded: AIzaSyAQ9x9vMDWrRfNL21hu2I4iCIN45BVtniw in AndroidManifest.xml:22 and AIzaSyCOmv1TLhNOfXKPIEVDwe196BWMnRHWVcI in AppDelegate.swift:11. These are extractable from any shipped binary — console-side restriction is the only defence. An unrestricted key on a billed project is an open invoice.

S2Add crash reporting

Zero crash visibility exists — grepping for crashlytics or sentry returns nothing. The Firebase project newpower-bgx is already provisioned, so firebase_crashlytics is a near-free addition. Shipping a first release with no crash telemetry means the first production defect is invisible until a user reports it.

S3Theme and language break after logout

AuthService.logout() calls resetGetIt() un-awaited, and resetGetIt is itself async but calls setupGetIt() without awaiting. That replaces the ThemeNotifier and LanguageManager singletons while MyApp's two ValueListenableBuilders still hold references to the originals. After a logout, theme and language switching silently stop working until the app is killed.

S4Clear secure storage on first run after install (iOS)

The iOS Keychain survives app deletion. A reinstall reads the previous user's refreshToken and deviceId from SecureStorageHelper and resumes their session.

S5Remove DeviceCompromisedApp

device_compromised_screen.dart:73 calls exit(0). It is dead code — never referenced — but Apple rejects programmatic termination. Leave no such call in a submitted binary.

S6Never flip FeatureFlags.offlineSyncEnabled

The analyzer confirms _retryOfflineQueue is unreferenced: nothing in DioFactory subscribes to connectivity. With the flag on, _enqueueOfflineRequest parks the handler and nothing ever calls _retryOfflineQueue — every GET during a network blip hangs for the full three-minute timeout. The flag is correctly false; the plan must ensure it ships that way.

S7Replace the raw print() security logger

dio_factory.dart:773 logs endpoints and failure details to unfiltered device logs in release.

S8Add ITSAppUsesNonExemptEncryption = false to iOS Info.plist

Without it, every single TestFlight and App Store upload stalls on the export-compliance question.

  • hive / hive_flutter serve only the disabled offline feature — but main.dart calls Hive.initFlutter() and OfflineQueueStore imports it, so removal means touching suspended code. Leaving them is the lower-risk choice.
  • Downscale the onboarding PNGs — onbarding1/2/3.png are 2.78 MB combined out of a 65 MB fat APK.
  • Repo hygiene: photo_2026-08-21_18-38-04.jpg, image.png, flutter_01.log, the deleted index (2).html, and roughly 600 KB of .md specs sit in the repository root.
  • Clear the 6 analyzer infos and warnings.
  • Remove the web/, linux/, macos/ and windows/ platform folders — firebase_options.dart explicitly throws on all four.
  • Add an iOS notification-permission priming screen before PushService.initialise() fires the OS prompt on MainScreen.initState.
  • Add CFBundleLocalizations for Arabic so the App Store listing shows both languages.
